## 一、FDE 的定义与角色定位

### 1.1 各嘉宾对 FDE 的定义

| 视角 | 定义 | 提出者 |
|------|------|--------|
| 连接者 | AI 技术与实际业务之间存在巨大割裂，FDE 是连接者，去解决技术和业务错层的问题 | 陈文武（工业领域） |
| 最后一公里 | 帮助 AI 落地企业、打通"最后一公里"的人 | 景白（跨境电商） |
| 低成本高定制 | 以极低的人力和物力成本规模，去实现高定制的数字化服务 | 李可木（建筑/国企） |
| 翻译+家政 | 像翻译也像家政，帮企业梳理流程、打通系统，了解业务需求再去实现 | 李志杰（制造业甲方） |
| 产品+实施 | FDE 不是全栈一个人干所有，本质是产品经理+实施顾问 | 韦妮（比亚迪） |
| 岗位组 | FDE 不是一个岗位，而是一个岗位组，需要多人协作 | 张进华（AI应用工程师） |
| 范式/模式 | FDE 是一种范式、一种模式，是 AI 落地的一种模式 | 张进华 |
| 赛博包工头 | FDE 像包工头，带着一帮 AI/agent 去企业里建"赛博大楼" | 李可木 |

### 1.2 FDE 与 OPC 的区别（Lawrence/明哲总结）

- **OPC**：更多是快速规模化，做大东西
- **FDE**：不一定知道自己要做什么产品，先驻扎到现场，观察企业需要什么样的 AI 技术去做提效
- 核心差异：FDE 是"找到问题"，OPC 是"规模化解法"

### 1.3 FDE 的两大类型

- **驻场 FDE（外部）**：以第三方身份进入企业，做项目交付
- **甲方 FDE/Building FDE（内部）**：在企业内部工作，做内部提效和改革（类似 Building skill 的概念）

### 1.4 FDE 的两阶段角色演变（陈文武）

1. **推动者阶段**：选一个高 ROI 的小点切入（如帮员工处理 Excel），先做出来效果，逐步辐射影响更多人
2. **Breaker（打破者）阶段**：进入深水区后发现，阻碍一切的是流程本身，需要外部人来做流程重构——内部人因关系复杂无法打破现有架构

## 二、FDE 落地案例详解

### 2.1 工业制造领域（陈文武）

**案例1：图纸转换提效**
- 企业规模：年营收 4000 万
- 痛点：客户订单图纸转换为内部图纸，原来需 3-4 天
- 方案：AI 辅助图纸转换
- 效果：缩短至 1-2 天（减少一半时间）
- 延伸：接入报价体系后，从订单进来到报价仅需半天
- 背景：该企业一个批次生产周期 7 天，其中办公室处理占 3-4 天，省下 2 天对生产价值巨大

**案例2：研发型企业全面提效**
- 企业规模：年营收 1 亿+
- 行业：设备研发（含电子、结构、光学）
- 策略：
  - 先搞定软件和嵌软人员用 Codex（研发老总最初不抗拒这部分）
  - 研发老总抗拒对电子/结构/光学做 AI（认为 AI 画不了图）
  - 关键动作：采访底下员工 → 发现他们一天 8 小时有 4 小时在处理文档和搬 Excel
  - 把调研结果给研发老总看 → 老总开会确认 → 接受
- 效果：文档工作被替代 + 顺手做了产品经理的 Skill（调研渠道+写方案方式）→ 产品经理的交互也自己做了 → UI 工程师只负责美学、不需要做交互 → 那个 UI 同事正在转岗

**核心洞察**：流程被加速，有的环节甚至被砍掉，组织结构因此变化

### 2.2 跨境电商领域（景白）

**案例：选品自动化**
- Before：3 个人 3-4 天，筛选出一周 2-3 个考虑点给老板拍板
- After：20 分钟跑出 1-3 个选品方案
- 效果：直接踩中上半年已开品的全部产品

**核心洞察**：AI 改造不只是加速原有流程，而是改变整个工作流架构——比如 Skill 定时执行，员工 9 点到岗时 AI 已经把繁琐工作处理完了，人工只需介入核心工作

### 2.3 建筑/国企领域（李可木）

**案例1：经济管理 OCR 自动化**
- 痛点：十几个工地项目每月收几十张报表，涉及香港和内地两套制度和口径差异
- 原来：每月花 3-5 天处理报表（一个工作周）
- 方案：用 agent 处理 OCR、非结构化 PDF/扫描件/图片/收据/发票
- 效果：现在 1 小时清完

**案例2：数据大屏/可视化平台**
- 原来方式：招投标 3 个月 + 中标 + 开发 → 1-2 年
- 现在：FDE + 业务人员一起，快速做出符合心意的大屏
- 实际使用：真的在用大屏管项目、追踪、预警

**案例3：考勤系统整合**
- 痛点：多个工地用不同考勤方式（纸质、打卡机），十几个系统混在一起
- 方案：定制化数字系统整合
- 状态：推进中（项目太多）

### 2.4 服装制造业领域（李志杰，甲方FDE）

**案例1：工艺单自动爬取**
- 原来：每月 22 小时人工从客户网站/PLM 系统下载工艺图和资料
- 方案：AI + SD 自动爬取
- 效果：每月不到半小时

**案例2：Ticket 归档**
- 原来：100+ 小时
- 效果：2-3 小时

**案例3：翻译（斯凯奇代工）**
- 痛点：设计师图纸是英文或韩文，人工翻译 15 分钟/个，每月约 200 个
- 方案：AI 翻译 + 行业词库
- 效果：30 秒/个
- 关键难点：行业黑话需要收集词库

**方法论**：先不急于上知识库/agent（不稳定），先用稳定方式（AI 扣点/程序化）建立信任，后续再上 agent 和 CLI

### 2.5 外贸领域（李哲潇）

**案例：销售填表提效**
- 原来：员工每天花 3-5 小时对照图纸填表
- 效果：每个员工不超过 10 分钟处理简单事务

### 2.6 物流调度领域（李东升，深圳大学）

**案例1：货车智能调度 Agent**
- 代替调度员手动调单/派单

**案例2：ERP 系统**
- 两个月内为公司开发上线可用的 ERP 系统
- 过程：跟工程师/项目经理谈需求 → 写 DES → 执行 → 上线

### 2.7 IT 服务领域（李正昌，Shopee）

**案例：IT 工单智能化**
- AI 周报自动整理分析工单数据
- 自动从已关单的工单中整理客服问答对，沉淀到知识库
- Agent 机器人识别用户问题后自动执行操作（改网络配置等），在机器人阶段直接闭环

### 2.8 蛋糕店案例（参会者）

- 痛点：微信流转订单，厨房手工在 Word 打印再传递
- 方案：用 vib coding 做了工程级的单据管理产品
- 核心难点：**微信是 FDE 最大的一道坎**——用爬虫爬 Windows 端微信，爬了 3 年被警告

### 2.9 潮玩行业（袁林局长分享，东莞滨海湾）

- 潮玩从设计到成品 13 个环节
- 传统周期：100 天
- AI 改造后：**压缩到 45 天**（节省一半时间）
- 设计环节从 2 天压缩到半天（节省 3/4）

## 三、企业为什么需要 FDE

### 3.1 核心论点

| 论点 | 提出者 |
|------|--------|
| 企业自己不知道需要，但做完改变后就觉得太有用了 | 陈文武 |
| 认知到 FDE 存在的企业有前沿意识，不需要的企业会被末位淘汰 | 景白 |
| 大模型进入真实企业环境不知道 CRM/ERP/MES 等系统口径，需要 FDE 梳理 | 李志杰 |
| 大模型公司（智谱、MiniMax）和云厂商（钉钉、阿里云、飞书）也需要 FDE 来卖企业 | Lawrence |
| 市场上 95% 以上的工厂没有 AI 人员，无法自己解决 | 袁林局长 |

### 3.2 FDE 的不可替代性

- **内部人无法打破架构**：老板希望内部人做，但内部人因关系复杂无法当 Breaker（陈文武）
- **外部咨询公司的速度优势**：像麦肯锡，速度快，有 knowhow 库（Lawrence）
- **企业希望转化 FDE 为内部人**：因为工业数据有壁垒，老板不想让外部人带走（陈文武）
- **但有过河拆桥风险**：导演/老板会让内部团队抄外部 FDE 的 skill 和经验（欧总，硅谷经验）

## 四、FDE 介入前后的变化

### 4.1 流程层面
- 单点提效 → 整体加速 → 流程缩短 → 有的环节被砍掉
- UI 工程师转岗的案例说明组织架构正在被 AI 重塑
- 从"原有流程上提效 10-20%"到"改变整个工作流架构"

### 4.2 员工层面
- 从抗拒 → 主动来问（因为文档工作被替代后更轻松了）
- 从"忙碌但没有产出"→ 解放出来做更有价值的工作
- 种子效应：一个软件人员用 AI 提效后，会影响硬件人员也用 AI

### 4.3 老板层面
- 从"觉得提效不大"→ 催着驻场
- 从"叫不到人"→ 看到员工作有效产出
- 老板认识到：阻碍企业的是流程本身

### 4.4 数据层面
- 从纸质/非结构化 → 结构化数据 → 数据资产
- 以前做数据分析/预测没有基础，现在开始加速形成

### 4.5 组织形式
- 组织架构可能被重置/重建（冯文：公司从 140 多人裁到 30 人）

## 五、FDE 项目沉淀

### 5.1 企业获得的沉淀
1. **利润/效率**：制造业 1% 提效都巨大（行业极卷）
2. **Skill 库**：成为企业重要资产
3. **数字化基础**：流程确定、数据结构化
4. **知识沉淀**：人走了工作能交接，企业稳定性提升
5. **半自动化自更新 Skill**：带日志系统和迭代机制

### 5.2 团队获得的沉淀
1. **方法论**：项目申请 → 量化评估(ROI+技术难度) → 人员分配 → 开发 → 交付
2. **共性架构**：从多个中小企业项目中抽离共性，开源化，让新入行 FDE 快速上手（陈文武团队在做）
3. **可复用方案**：不同企业的人事/财务系统大差不差，很多东西可复用

### 5.3 个人获得的沉淀
1. **金钱**：从咨询阶段就开始收费，到交付结果付费
2. **行业 Knowhow**：发现行业间的共性问题，可能将上下游组合
3. **超级个体/超级团队**：组织架构不再是前后端分工，而是突出擅长部分、长短互补
4. **可迁移能力**：了解每个部门/岗位做什么，对进入不同公司有帮助

## 六、AI Native 的深度理解

### 6.1 AI Native Person（ANP）

| 视角 | 定义 | 提出者 |
|------|------|--------|
| 思维习惯 | 遇到问题不按传统思维解决，想能不能用 agent/product 在很短时间内做出来 | 观众 |
| 生活习惯 | 出门必带录音豆+Loki，像一种生活认知 | 冯文（AI 博主） |
| 去中间层 | all in context，把所有东西交给 AI，让 AI 足够了解 context，直接数据层→交付层 | 观众 |
| 人机协同 | 任何事情先尝试让 AI 解决，哪怕只能解决 60%。所有工作都在手机/微信/飞书通过 agent 完成 | 陈文武 |
| 认知重建 | 不断重塑自己的认知，因为 AI 每隔几个月就有大变革 | 欧总（硅谷经验） |
| 思维表达 | 把脑中模糊概念通过 AI 交互以产品形式表达出来 | 大学生参会者 |

### 6.2 AI Native 的四要素（Lawrence 总结）
1. **重塑工作流**：用 AI 重新思考做事的方式
2. **Context 收集**：把周遭环境、对话全录下来做上下文
3. **去掉中间态**：直接端到端，context in → output out
4. **认知不断重建**：随 AI 演进而拓宽认知

### 6.3 AI Native Company

- 由 AI Native Person 组建，但不只是人的叠加
- 自上而下 vs 自下而上：
  - **自上而下**：老板给压力，效率较慢、容易出错
  - **自下而上（推荐）**：从个别超级个体涌现成超级团队，触发因素多种（老板激励、FD 带入 AI 氛围等）
- AI Native 是一个**比率问题**：不是 0 或 1，而是企业里多少人善用 AI、节点间沟通是否数字化

### 6.4 FDE 在 AI Native 过程中的角色
- **文化带入者**：带入 AI 氛围，从下而上涌现
- **问题命名者（Name the Issue）**：最多时候企业描述不出问题在哪，FDE 的核心工作是定位问题
- **推动者→Breaker**：先推单点，再打破流程

### 6.5 人与 AI 协作的特殊视角（艺术家案例）
- 艺术家更接受 AI：Photoshop 换 AI 工具，都是工具/搭档
- 人跟 AI 是一起互动、共同创造
- 不是"AI 抢饭碗"或"要么人做要么 AI 做"，而是协作

## 七、FDE 需要具备的能力

### 7.1 能力全景

#### 第一维度：业务能力（权重最高）
1. **现场业务调研**：弄清真实业务流程、员工历史习惯
2. **需求翻译**：把老板模糊需求（"帮我把 AI 用起来"）翻译成可落地的业务
3. **场景判断**：输入输出过程是否确定、人工能否描述清楚
4. **行业理解**：有行业经验则更擅长，或在某行业深耕
5. **需求挖掘**：员工不配合/有矛盾时，需要智慧和领导关系来获取真实信息

#### 第二维度：AI 技术能力
- 不需要顶尖算法，但要知道 AI 能做什么、不能做什么（懂边界）
- 原型输出：做 MVP/demo 做给客户展示
- 知道代码怎么实现（对开发有基本认知）
- 多模型选择：不同场景选择不同模型（不一定要用最好的模型）

#### 第三维度：沟通/组织推动能力
- **对老板**：站着甚至平视，讲价值不讲技术
- **对员工**：半跪着蹲在旁边，用心讲清楚"我不是来替代你的，我来帮你解决麻烦事"
- 消除员工对 AI 的抵触和裁员焦虑
- 与业务人员交朋友，用共情获取真实业务流程
- **进场第一件事是建立信任关系，不要上来就讲技术**

#### 第四维度：商务/财务能力
- **财务能力（被忽视但极重要）**：
  - 看懂财报、设计可衡量的 ROI 指标
  - 避免模糊指标导致扯皮和拿不到尾款
  - 合同条款设置
  - 提出者张进华：有超过中级会计师的财报阅读能力
- **商务谈单**：给企业算清楚投入产出比

#### 第五维度：快速验证与交付
- Demo 不需要很多功能，但要能解决实际问题
- 用浏览器自动化测试做快速迭代验证
- 验证-返工-验证循环是最花精力的

#### 第六维度：持续学习
- AI 大模型持续更新迭代
- 业务模式随市场变化
- 不是一次性交付

### 7.2 两类转型路径（李维斌）

| 来源 | 优势 | 需要补齐 |
|------|------|----------|
| 开发者/Builder（软件公司开发、产品经理） | 技术能力 | 业务理解、沟通、流程拆解 |
| 传统咨询顾问（埃森哲、IBM 等） | 商务信任、业务沟通、客户关系 | 技术认知（不需要特别深入，简单 Docker/部署/agent 平台即可） |

### 7.3 能力如何建立

| 能力 | 建立方法 |
|------|----------|
| 业务调研/需求拆解 | 每天跟豆包/ChatGPT 聊半小时（70%时间自己讲，30%看），练习口头表达 |
| AI 能力 | 高效使用半个月，知道能力边界即可 |
| 项目交付推动 | **只有实战**——找到愿意信任的老板，进入业务现场 |
| 商业获客 | 找合作方（行业协会、园区、政府、代理商），不要单打独斗 |
| 销售/演销 | 需要 100 场以上演练，学会挖痛点+共情 |
| 财务能力 | 学会计基础、看财报、设计可量化指标 |

### 7.4 FDE 团队配置建议
- **理想组合**：商务能力者 + 业务领域专家 + AI 落地能力者
- 一个人无法同时做好商务+技术+交付
- 参考律所模式：合伙制、各取所长

## 八、商务/销售方法论

### 8.1 如何向不懂 AI 的老板解释价值并建立信任

1. **不要讲技术**：讲技术老板听不进去，5 分钟之内一定会走偏
2. **挖痛点+共情**：知道老板痛苦在哪里，从痛点切入
3. **讲结果不讲过程**："这个东西解决完可以帮你提效多少"
4. **讲不用的代价**："如果你不用，就会死掉"，而不是"你要用"
5. **用老板的语言**：比如用 EPC（设计-采购-施工）这类老板熟悉的词来类比 AI 项目
6. **筛选客户**：验证付费意愿——让对方出基酒/差旅/驻场诊断费，作为诚意证明
7. **先交朋友**：进企业第一件事是建立信任关系，至少一半时间不要讲技术

### 8.2 培训咨询公司的销售能力（张总分享）

- **演销能力**：会演讲 + 会销售 + 会表演 + 会通过情绪感染
- 两天课程现场成交 100 万（单一客户）
- 一场活动成交 400 万-1000 万+
- 客单价：培训产品 4-8-12-30 万，按成交付费
- 核心：让老板信任你、崇拜你、哪怕交个朋友花几十万都开心

### 8.3 商务分润模式
- 商务/渠道方：**35%-40%**
- 交付方：60%-65%
- 专业化分工：商务交给能建立信任的人，自己专注交付

### 8.4 行业客户的获取渠道（李维斌）

1. **行业协会挂牌**：与各地电商/制造行业协会合作挂牌"AI 赋能中心"→ 获得政府背书+免费物业
2. **园区/政府合作**：政府有政绩需求，挂牌是标杆
3. **传统代理商**：微软/戴尔/SAP 的代理商自带客户
4. **BOSS AI 私教**：让 FDE 与老板 1v1 结对，辅导老板用 AI
5. **老板帮帮帮**：线下俱乐部形式，潜移默化植入 AI 理念，不强行推销

### 8.5 报价与时间策略
- **美业案例**：60 天 30 万，以结果为导向，达不到退款
- 时间是精密计算的——太短老板怀疑"凭什么这么短收这么多钱"，太长老板不接受
- 行业越熟悉，越了解多少钱多少天可接受

## 九、给 FDE 后来者的经验

### 9.1 进场策略
1. **从点到线到面**：先做单点突破（如帮员工处理 Excel），再辐射
2. **先做工具培训**：教员工用 Workbody/Codex → 做系统 → 做粘合剂，培训提效最快
3. **从咨询阶段就收费**：驻场诊断收费，基酒+差旅是诚意证明
4. **需要一号位/二号位支持**：授权至关重要

### 9.2 话术技巧
- **不要问**："你觉得现在哪些工作是 AI 可以替代的？" → 员工说"没有"
- **要问**："你现在有没有哪些工作做起来比较烦人？" → 员工说"有有有"
- 不要跟业务人员说"AI 提效"，要说"帮你解决麻烦事"

### 9.3 信任建立
- 先找熟人/朋友介绍，比冷启动有效得多
- 展示过往案例证明价值
- 让老板感受到你站在他的角度

### 9.4 运营方法论
1. 准备**案例库**：不同项目沉淀可复用 skill 和流程（不同行业的中台问题是通用的）
2. 每次业务沟通都**全程录屏/录音**，用飞书妙记整理复盘
3. **引导员工自己做 agent**：培养学习能力强的人，他们做的 agent 比技术人员做的更好
4. **安插内鬼**：在企业里培养一个人成为 AI 推动者

### 9.5 避坑指南
1. **先做面太大不行**：中小企业要的是点，不是面。但做点必须先有面的认知
2. **制造业需要确定性**：不能用每次生成新代码的方式，要做成确定性的程序/skill
3. **微信是最大的坎**：中小企业 context 在微信里，需要人肉处理
4. **不要高估自己**：不是每个人都能做六边形战士，要学会合作
5. **获客要找对决策人**：判断二代是否有实权——看天眼查是否有关联公司股权

### 9.6 收费模式
- 订阅制（提供后续维护+增值服务）
- Skill 长期收费（有 API 调用）
- 按项目阶段收费（咨询→诊断→交付）
- 按结果付费/分润

### 9.7 数据安全处理
- 本地小模型（3B/4B）做数据脱敏 → 上传云端大模型 → 结果回来 → 还原
- 脱敏对象：用户个人信息（身份证/手机号/姓名）、财务具体数据
- 趋势分析可以加随机数（不超三西格玛），精确计算需本地模型
- 企业版飞书等有数据不用于训练的协议
- 买保密 API 比本地部署成本更低（本地部署需要运维人员）

### 9.8 出海建议
- **东南亚/澳洲/中亚**：竞争小、付费意愿好、不卷
- **哈萨克斯坦**：完全没有 AI 应用和模型，从 token 到服务器到培训整套输出
- 国内 1500/月 → 200/月，海外给个小费都比这多
- 发 Cold Email 回复率都比国内高很多

## 十一、关键技术讨论

### 11.1 代码 vs AI 生成代码
- AI 可生成 80% 代码，但需要 Code Review
- 涉及并发、安全、数据安全等工程问题仍需人工把控
- 大型系统需要解耦：子系统管理子系统，分布式架构
- Anthropic 80% 是代码生成，包括自进化

### 11.2 Skill vs Agent vs 传统程序
- **制造业**：需要确定性，更适合做成固定程序/Skill（SOP+工具），而非开放 agent
- **Skill 本质**：AI 的 SOP——有指导书+工具（CLI、MCP），尽可能减少幻觉
- **Agent**：适合需要灵活判断的场景，但需要接受不确定性
- **先程序后 agent**：先建立信任，再上 agent

### 11.3 工具链
- Workbody、Codex、Coze、Kargo、飞书妙搭
- Hermes/Proco 接 bot
- 飞书多维表格 + 自动化流程
- 录音豆（飞书/安克/钉钉）→ 飞书妙记 → 复盘
- 浏览器自动化测试用于快速迭代

### 11.4 系统架构思路
- **知识与数据底座** + **协同层** 两步走
- 不需要一开始就上 RAG/知识库，先做稳定的东西
- 要考虑企业已有的 Harness（飞书妙搭/企业微信/阿里方案）

## 十三、散场交流补充要点

### 13.1 FDE 的现实困境
- 外部 FDE 项目周期短（1-2 个月），完成后可能被抛弃
- 解决方案：订阅制、后续维护增值、Skill 长期收费
- 人的价值在于：AI 不能百分百不出错，**人=背锅兜底**
- 增效 > 降本：投入 1 元获得 2 倍收益，而不是单纯裁人

### 13.2 项目推进经验
- 工厂系统高度耦合，做全链路协同层价值最大，但需要从一个点切入
- 中小企业老板付费意愿不高（尤其制造业毛利低），需要筛选
- 厂二代不一定有实权：看天眼查是否有股权关联是最快判断方法
- 完整方案+Demo+培训课件都做好，卡在获客是常见问题

### 13.3 职业发展
- 35 岁技术人员转型方向：管理 or 咨询顾问（FDE 是很好的第三条路）
- 在校学生也能做 FDE：大二学生已在链接项目
- "事情就得出来干，躺在企业干不成" — 某些工作必须独立出来做

### 13.4 国内竞争现实
- 一个好模式 3 天被复制
- 技术人干不过会销/销售
- 解决方案：出海 or 找专业商务合作
