# 实时日志控制台：AI 编码提示词

## 已确认的参考特征

- 在线地址未登录时会跳转到 AstrBot 登录页，无法直接查看 `/platforms` 的完整页面。
- 附件中的日志组件采用深色控制台布局，普通状态高度约 `300px`。
- 顶部左侧是 `DEBUG / INFO / WARNING / ERROR / CRITICAL` 五个多选筛选 Chip，选中时带勾。
- 顶部右侧是全屏按钮；主体按 `时间 → 来源 → 级别 → 消息` 展示结构化日志。
- 附件中可确认的行文字颜色：INFO 为 `rgb(114, 196, 204)`，WARNING/WARN 为 `rgb(212, 185, 94)`。

下面的方案只借鉴通用的信息架构和交互，不复制原站品牌、Logo、真实日志、专有文案或源代码。

## 三种设计方向

### 方案一：极简接收器

组件只公开 `append()` 和 `clear()`。筛选、全屏、缓冲、滚动跟随全部由组件内部处理。最容易接 WebSocket/SSE，也最不容易误用，但父组件不能精细控制搜索、导出和筛选状态。

### 方案二：高度可配置

支持自定义日志级别、颜色、插槽、搜索、暂停、导出、远端筛选和动态行高。适合做通用组件库，但 Props/Events 很多，首版成本和测试面较大。

### 方案三：运维场景优先（推荐）

使用小型 `feed.append()` API 接收高频日志，筛选和选中状态保持声明式。加入自动跟随、离底提示、异常跳转、虚拟列表与详情面板，兼顾性能和日常排障效率。

最终建议：采用方案三的体验与性能设计，同时保留方案一的简单接入方式；第一版不实现方案二的复杂插槽和远端查询。

## 可直接复制给编码 AI 的提示词

```text
请为我的 Vue 3 + TypeScript + Vuetify 3 管理后台实现一个原创的实时日志控制台，不要复制任何现有产品的品牌、Logo、真实日志、专有文案或源代码。它只借鉴通用的深色运维控制台布局。

请先检查当前项目的目录结构、组件规范、主题变量、图标库和测试框架，再按现有风格落地，不要新建第二套设计系统。若项目不是 Vuetify，则使用项目已有组件库实现同等效果。

一、视觉结构

1. 组件名为 RealtimeLogConsole，默认高度 300px，宽度 100%，背景 #1e1e1e，边框使用低对比深灰，整体保持紧凑、专业、长时间阅读不刺眼。
2. 顶部工具栏固定在组件顶部：
   - 左侧显示 DEBUG、INFO、WARNING、ERROR、CRITICAL 五个小尺寸多选 Chip。
   - Chip 选中时显示勾，不选中时降透明度；不能只靠颜色传达状态。
   - 建议颜色：DEBUG #9CA3AF、INFO #72C4CC、WARNING #D4B95E、ERROR #F87171、CRITICAL #C084FC。
   - 右侧显示当前可见条数/总条数、连接状态和全屏图标按钮。
3. 日志主体使用等宽字体，桌面端 13px/20px；每行固定四段：时间、来源、级别、消息。
4. 桌面端建议列宽：时间 112px、来源 150px、级别 88px、消息占剩余空间。时间显示 HH:mm:ss.SSS，完整时间放在 title 或详情中。
5. 默认单行不换行，超长消息允许横向滚动或省略；不要给整行铺高饱和背景，只对级别文字、徽标或左侧细线着色。
6. 空状态要区分“尚无日志”和“当前筛选没有匹配项”。

二、数据接口

使用以下核心类型，可结合项目规范调整文件位置：

type LogLevel = 'DEBUG' | 'INFO' | 'WARNING' | 'ERROR' | 'CRITICAL'

interface LogEntry {
  id: string
  timestamp: number | string
  source: string
  level: LogLevel
  message: string
  attributes?: Readonly<Record<string, unknown>>
  traceId?: string
  sequence?: number
}

对外提供小型命令式接口：

interface RealtimeLogConsoleHandle {
  append(entry: LogEntry | readonly LogEntry[]): void
  clear(): void
  followTail(): void
  toggleFullscreen(force?: boolean): Promise<void>
}

父组件可以用 ref 调用这些方法。不要把 WebSocket 地址和鉴权硬编码进展示组件；同时提供一个演示页面，展示如何把 WebSocket 或 SSE 消息标准化后传给 append()。

三、必要交互

1. 五个级别默认全部启用，点击 Chip 可独立开关；至少保留一个启用项，或明确显示“无级别被选中”的空状态。
2. 新日志到达时：只有用户本来就在底部附近才自动滚到底部。用户向上查看历史后不得抢走滚动位置，而是在右下角显示“↓ N 条新日志”，点击后回到底部并恢复跟随。
3. 支持全屏：优先 Fullscreen API，失败时使用 position: fixed 的 CSS 降级；Esc 退出并恢复原滚动位置。
4. 加入搜索框，支持 message/source 的普通文本搜索；使用文本片段渲染高亮，禁止 v-html。
5. ERROR 与 CRITICAL 的计数始终可见，提供“上一个异常/下一个异常”按钮；定位后短暂描边，不要持续闪烁。
6. 单击选中日志；双击或按 Enter 打开详情抽屉，展示完整时间、source、level、message、traceId 和格式化 attributes，并提供复制当前日志 JSON 的按钮。
7. 清空按钮必须命名为“清空本地视图”，明确不会删除服务端日志；执行前使用项目已有的确认交互。

四、性能与安全

1. 内部使用有界环形缓冲区，默认最多保留 5,000 条；超出后淘汰最旧记录，并在界面显示累计淘汰数量。
2. 高频 append 使用队列加 requestAnimationFrame 或约 50ms 批处理，避免每条日志触发一次完整重绘。
3. 日志列表使用项目已有的虚拟列表；若项目没有，先实现固定行高窗口化，不要引入大型依赖。
4. 按 id 去重；sequence 存在时优先用它稳定排序，否则使用 timestamp 加接收顺序。
5. 所有日志内容必须按纯文本渲染，严禁 v-html，避免日志内容造成 XSS。
6. 组件卸载时清理定时器、观察器、事件监听和全屏状态。

五、响应式与可访问性

1. 小于 600px 时改为两行日志：第一行时间/级别/来源，第二行消息；筛选 Chip 横向滚动，次要操作收进更多菜单。
2. 移动端全屏使用 100dvh 和 safe-area inset，触摸目标至少 44px。
3. Chip 使用 aria-pressed，全屏、搜索、异常跳转和清空按钮都有准确 aria-label。
4. 不要给每条实时日志设置 aria-live；只低频播报连接状态、新增数量和错误计数。
5. 支持快捷键：/ 聚焦搜索、End 回到最新、F 切换全屏、Esc 退出当前层级；输入框聚焦时禁用单键快捷键。

六、输出与验收

请交付：
1. RealtimeLogConsole.vue。
2. 独立的 types.ts 和 useLogFeed.ts（或符合项目规范的等价结构）。
3. 一个使用虚构日志数据的演示页面，不出现真实用户、账号、二维码链接、IP、Token 或聊天内容。
4. 与项目测试框架一致的测试，至少覆盖：级别筛选、自动跟随停止/恢复、缓冲区淘汰、全屏降级、搜索高亮、纯文本安全渲染、清空本地视图。
5. 说明修改了哪些文件、如何运行、如何接入真实 WebSocket/SSE。

实现前先给出不超过 8 条的文件修改计划；随后直接编码、运行测试并修复失败，不要只输出伪代码。
```

## 建议验收清单

- 五个级别可独立筛选，颜色和文字语义一致。
- 300px 普通模式与全屏模式都无布局跳动。
- 用户向上滚动后，新日志不会抢走阅读位置。
- 5,000 条以上持续追加时内存有上限，界面仍可流畅滚动。
- 超长消息、中文、Emoji、换行和疑似 HTML 字符串都能安全显示。
- 窄屏不出现不可操作的按钮或被遮挡的日志内容。
- 示例数据完全虚构，不包含附件中的真实聊天、账号、二维码或服务地址。
