## 二、核心知识点整理

### 2.1 带声音AI视频生成的两种方式

| 方式 | 流程 | 优点 | 缺点 |
|------|------|------|------|
| **先出画面后配音**（早期主流） | 模型先生成整段画面 → 再交给另一套音频模型补对白/环境声/脚步声/碰撞声/BGM | 容易训练，方便组合不同模型 | 画面已固定，声音只能追着画面配；本质类似传统后期配音，音画非同步创作 |
| **音画联合生成**（先进方向） | 画面和声音两团噪声从头到尾一起计算 → 人物开口/嘴型/脚步/碰撞/环境声在同一段生成中共同决定 | 声音不是后期贴上去的，而是和画面一起算出来的，天然契合 | 技术更复杂，尚在发展中 |

### 2.2 音画联合生成的两种技术路线

**路线一：双处理路径 + 跨模态注意力交互**
- 给视频和音频各安排一条独立处理路径
- 通过跨模态注意力让两边在生成过程中不断交换信息
- 比喻：两个小组一边干活一边互相汇报进度
  - 画面告诉声音："现在人物正在张嘴"
  - 声音告诉画面："这一刻正在说什么，节奏有多快"

**路线二：单统一模型共同处理**
- 直接把视频和音频数据放进同一个统一模型里处理
- 比喻：把画面草稿和声音草稿全部摆到同一张桌子上，交给同一个大脑统一判断

> 两种路线结构不同，但目的相同：让画面和声音不只是在最后对齐，而是在生成过程中就互相影响。

### 2.3 Minimax H3 的工作机制（统一处理路线）

```
视频输入 ──→ 视频VAE压缩 ──┐
                              ├──→ 打包为同一条多模态序列 ──→ H3 OmniTransformer 联合计算/预测
音频输入 ──→ 音频VAE压缩 ──┘
                                                              ↓
                                              采样器输出 = 同时包含视频+音频的打包数据
                                                              ↓
                                          视频VAE解码 ←── 分别取出各自部分 ──→ 音频VAE解码
                                              ↓                                          ↓
                                          视频画面                                    声音音轨
                                              ↓                                          ↓
                                              └────────── 视频合成节点 ──────────────────┘
                                                                   ↓
                                                              MP4文件
```

**关键要点**：
- H3 **不是**两套独立的去噪网络每步互相打招呼，而是把视频和音频放进**同一个生成系统**，由同一个核心模型一起处理
- 工作流中出现两个VAE的原因：视频VAE负责解码画面部分，音频VAE负责解码声音部分，它们像两个不同的翻译器
- 视频合成节点做的只是**封装和写入文件**，音画关系早在前面的联合采样过程中就已生成
- 画面和声音可能有不同的长度参数，可理解为两套不同的时间刻度（视频按帧计算，声音按连续音频数据计算），最后必须对应到同一段时长——这解决的是长度换算问题，不代表运行着两套独立AI模型

### 2.4 当前音画联合模型的能力边界

| 能力 | 现状 |
|------|------|
| 单镜头/短片段生成 | 擅长，几秒到十几秒 |
| H3最高分辨率 | 2K |
| H3最长时长 | 15秒 |
| H3音频 | 可直接生成原声立体声 |
| 多镜头自动切换 | 尚不成熟 |
| 长时间保持人物和场景一致 | 尚不成熟 |
| 输入完整剧本直接生成整部成片 | 尚不成熟 |
| 实际创作方式 | 分段生成 + 剪辑拼接 |

### 2.5 一句话总结

> 过去的视频模型是**先把画面做出来，再给画面配声音**；现在的音画联合模型则是**在同一次生成过程中，把画面和声音一起算出来**。H3的做法是把视频和音频数据打包到一起，交给同一个Transformer统一处理。

**[00:00:00]** 哈喽，小伙伴们大家好，欢迎回到本期的ComfyUI系列教学。在前面的三节内容里，我们已经把AI生图这条线完整走通了一遍。第一节熟悉了ComfyUI的操作界面，第二节从零搭建并跑通了文生图工作流，第三节则拆解了底层原理，扩散模型是如何把一团随机噪声一步步去噪成一张清晰画面的。打好了这个基础，从这一节开始，我们要正式踏入一个更有意思的领域，AI视频生成。

**[00:01:27]** 截止目前，带声音的AI视频生成，它大体可以分成两种方式。早期比较常见的是先出画面，后配声音。模型先按照普通视频生成的方式，把整段画面做出来，然后再把生成好的视频和提示词交给另一套音频模型，补出对白、环境声、脚步声、碰撞声或者背景音乐。这种方式比较容易训练，也方便把不同的模型组合在一起。但它的缺点也很明显，画面已经生成完了，声音只能在后面追着画面去配。虽然也能尽量把声音和动作对齐，但本质上还是先有视频，再做声音。跟传统的后期配音比较接近，音画并不是从一开始就一起创作出来的。现在更先进的方向叫做音画联合生成，大家可以把它理解成模型面前同时摆着两团噪声，一团最后要还原成视频画面，另一团最后要还原成人声、环境音和动作音效。

**[00:02:25]** 模型在生成过程中，不是先把其中一团擦干净，再去处理另一团，而是让画面和声音从头到尾一起计算，人物什么时候开口，嘴型应该怎么变化，脚什么时候落地，物体什么时候碰撞，环境里应该出现什么声音。这些内容都会在同一段生成过程中共同决定，所以最后的声音不是后期贴上去的，而是和画面一起算出来的。

**[00:02:50]** 不过音画联合生成并不只有一种固定结构，很多研究模型会给视频和音频各安排一条处理之路，然后通过跨模态注意力，让两边在生成过程中不断交换信息，可以理解成两个小组一边干活，一边互相汇报进度。画面这边告诉声音，现在人物正在张嘴，声音这边也会告诉画面。这一刻正在说什么，节奏有多快。还有一些模型会采用另一种方式，直接把视频和音频的数据放进同一个统一模型里处理。它更像是把画面草稿和声音草稿全部摆到同一张桌子上，交给同一个大脑统一判断。两种路线的结构不一样，但目的都是相同的，让画面和声音不只是在最后对齐，而是在生成过程中就互相影响。而我们这次使用的Minimax H3则更接近后面这种统一处理的方式。

**[00:03:43]** H3会先通过两套不同的VAE，把画面和声音分别压缩成模型更容易处理的数据。视频交给视频VAE，声音交给音频VAE。虽然它们在前空间里仍然是两种不同的数据，但接下来会被打包进同一条多模态序列，再交给同一套H3 OmniTransformer共同计算和预测。所以更准确的说，H3并不是两套独立的去噪网络，每一步互相打招呼，而是把视频和音频放进同一个生成系统里，让同一个核心模型一起处理。这也正好解释了为什么我们的comfyUI工作流里会出现两个VAE。视频VAE负责把生成结果里的画面部分解码出来，音频VAE负责把声音部分解码出来。它们的作用更像是两个不同的翻译器，一个把潜空间数据翻译成视频画面，另一个把潜空间数据翻译成可以播放的声音。采样器输出的其实是一份同时包含视频和音频的打包数据，两套VAE分别取出属于自己的部分进行解码，最后再由视频合成节点把画面和音轨装进同一个MP4文件里。所以最后这个合成节点做的只是封装和写入文件，并不是到了这里。

**[00:04:57]** 模型才开始让声音和画面对齐。它真正的音画关系早在前面的联合采样过程中就已经生成好了。如果在工作流里看到画面和声音拥有不同的长度参数，也可以把它理解成两套不同的时间刻度。视频是按照一帧一帧来计算的，声音则是按照连续的音频数据来计算的。两边记录时间的方式不同，但最后必须对应到同一段时长。这个过程解决的是视频帧和音频数据之间的长度换算，并不代表外面真的运行着两套互相独立的AI模型。

**[00:05:31]** 现阶段这类模型最擅长的仍然是几秒到十几秒的单镜头或者短片段生成。以H3为例，官方公开的能力是最高生成2K分辨率，最长15秒，并且可以直接生成原声立体声。至于多镜头自动切换、长时间保持人物和场景一致，以及输入一份完整剧本，直接生成整部成片。目前在实际创作中，通常还需要分段生成，再通过剪辑把不同片段组织起来。所以整件事用一句话概括就是，过去的视频模型是先把画面做出来，再给画面配声音。现在的音画联合模型则是在同一次生成过程中，把画面和声音一起算出来。而H3的做法是把视频和音频的数据打包到一起，交给同一个Transformer统一处理。同时为了方便小伙伴们学习和研究，我也把本期案例内容的使用说明整理成了文档。感兴趣的小伙伴可以在评论区自行领取。好的，那么小伙伴们，今天这期的内容我们先分享到这里，最后让我们用一首轻松的歌曲为今天的课程画上一个句号吧！
