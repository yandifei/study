## 二、核心知识点整理

### 2.1 扩散模型去噪原理（显影液比喻）

整个生图过程可以想象成**一张照片泡在显影液里**，画面从模糊噪点逐步浮现：

1. **初始状态**：只有一团杂乱无章的雪花噪点（由K采样器根据随机种子生成）
2. **迭代去噪**：每一轮模型判断哪些是噪声、哪些接近提示词描述的内容，去掉一小部分噪声，让画面朝提示词方向靠近一点
3. **逐步成型**：噪点→大致构图和轮廓→人物/物体/空间关系稳定→色彩/光影/材质/细节补充→完整清晰图片
4. **专业术语**：这个过程叫**扩散模型的迭代去噪**，也叫**反向扩散过程**

### 2.2 模型训练 vs 生成

| 阶段 | 起点 | 过程 | 目标 |
|------|------|------|------|
| **训练阶段** | 真实图片 | 人为加入已知随机噪声→让模型预测噪声→根据误差调整参数→海量图片反复进行 | 学会识别和预测噪声 |
| **生成阶段** | 纯随机噪声 | 模型预测应去掉的噪声→采样器/调度器推进到噪声更少的状态→提示词全程导航 | 从噪声一步步还原出图片 |

### 2.3 潜空间（Latent Space）

- **为什么需要**：1024×1024图片有超100万像素×3通道，直接在像素上计算太慢
- **怎么做**：用VAE将图片压缩（长宽各缩小约8倍），数据量缩小几十至上百倍
- **运算位置**：所有加噪、去噪、采样、运算全部在压缩后的潜空间中进行
- **还原**：算完后再由VAE解码放大回正常尺寸
- **这也是为什么准备画布的节点叫"空Latent"而不是"空图像"**

### 2.4 三大核心角色

```
提示词(文字) ──→ CLIP(翻译员) ──→ 条件向量(数字)
                                              ↓
空Latent ──→ 噪声画布 ──→ K采样器 ←── UNET(主模型/实际绘图)
                                ↓
                           潜空间图像
                                ↓
                           VAE(显影机) ──→ 成品像素图
```

| 角色 | 别称 | 职责 |
|------|------|------|
| **CLIP** | 翻译员 | 将人类语言提示词转换为模型能理解的条件向量（正向=靠近，负向=远离） |
| **UNET** | 主模型/绘图员 | 体积最大最关键，每轮接收噪声+条件向量，预测应去除的噪声量和画面调整方向 |
| **VAE** | 显影机/压缩器 | ①将大图压缩进潜空间；②将潜空间数据解码放大还原为可查看的像素图 |

### 2.5 完整数据流动流程

1. 提示词 → CLIP → 正向/负向条件向量 → K采样器
2. 空Latent → 随机噪声潜空间画布 → K采样器
3. K采样器 + UNET主模型 → 多轮迭代（每轮朝正向靠近、躲开负向）→ 跑完采样步数 → 潜空间图像
4. 潜空间图像 → VAE解码放大 → 成品图

### 2.6 K采样器六大核心参数

#### ① 随机种子（Seed）
- **本质**：生成初始噪声画布的起点编号，可视为图片的唯一身份标识
- **同种子复现**：模型、提示词、其他参数完全一致时，同种子理论上每次生成一模一样的图片
- **实用技巧**：
  - 构图满意只想微调细节/改措辞 → **锁死种子**，保住构图姿势布局，只变局部细节
  - 想要每次不同结果 → 设为**随机**

#### ② 采样步数（Steps）
- **本质**：擦噪声动作重复的轮次
- **规律**：步数越多→每轮调整幅度越小→画面越稳定完整，但生成时间线性增加
- **参考值**：
  - 加速优化模型（如Z-Image Turbo）：**8步左右**即可
  - 传统模型：**20–30步甚至更多**
- **注意**：不是越高越好，超过临界点后画质提升极微，纯浪费时间

#### ③ CFG值（无分类器引导强度）
- **本质**：模型每轮判断时听取提示词的约束程度
- **调低**：模型更多按自身训练规律发挥，画面更自然松弛，但与提示词贴合度低
- **调高**：模型非常执着地朝提示词方向靠，贴合度提升，但过高易出现：
  - 过度锐化
  - 颜色过饱和
  - 画面结构发僵
- **参考值**：
  - SD 1.5 / SDXL 时代：常见 **7–10**
  - 新模型：通常 **1** 就有很好效果
- **建议**：不同模型甜蜜点不同，需结合实际出图效果调试

#### ④ 采样器（Sampler）
- **本质**：每轮去噪时，模型完成噪声预测后，系统采用哪种数学算法计算下一步画面走向
- **常见类型**：Euler、DPM++ 2M、DPM++ SDE、UniPC 等
- **差异**：不同采样器在收敛速度、画面稳定性、细节表现、整体质感上有差别
  - 有些速度快，低步数也能出完成度不错的画面
  - 有些更擅长纹理和细节，但需搭配合适的步数与调度器
- **建议**：新手先用模型官方推荐或工作流默认参数，后续再对比调试

#### ⑤ 调度器（Scheduler）
- **本质**：去噪全程的节奏安排，决定从高噪声到低噪声过程中每个采样步骤处在哪个噪声等级、步骤如何分布
- **比喻**：去噪过程像一段路，调度器决定这十几步怎么安排——均匀分布？前大后小？还是集中在某个噪声阶段？
- **影响**：不同安排影响模型在构图、轮廓、纹理、细节上的计算分配
- **与采样器的关系**：
  - **采样器**决定每一步具体怎么走
  - **调度器**决定这些步骤在整段去噪路程中怎么分配
  - 同一采样器换不同调度器，画面细节、稳定性、质感可能变化
- **建议**：初学者先用官方默认搭配，知道它负责什么即可

#### ⑥ 去噪强度（Denoise）
- **文生图中**：通常固定为 **1**，代表从纯随机噪声完全重绘，与任何已有图片无关
- **图生图中**：核心参数
  - 值越接近1 → 加噪比例越高 → 越接近纯随机 → 结果越像重画，与原图关联度越低
  - 值越小 → 保留原图信息比例越高 → 结果与原图更接近，改动幅度更小
- **本质**：控制在原图基础上改动多少、保留多少的关键参数

### 2.7 参数串联总览

| 参数 | 控制环节 |
|------|----------|
| 随机种子 | 画面从哪个具体随机起点出发 |
| 采样步数 + 调度器 | 去噪过程走多少轮、每轮节奏如何分配 |
| 采样器 | 每轮采用什么计算方式和路径去除噪声 |
| CFG | 生成过程中对提示词的遵循强度 |
| Denoise | 初始噪声介入程度，即模型可对画面进行多大幅度的重新生成 |

**[00:00:00]** 哈喽，小伙伴们大家好！前面两节课我们已经简单认识了 comfyui 的操作界面，也亲手搭建了一套最基础的文生图工作流，正向提示词、负向提示词、K采样器、空latent，还有unet、clip和VAE，相信大家现在看着都已经有些眼熟了。

**[00:00:20]** 但工作流虽然跑通了，很多小伙伴心里可能还藏着一个问题，我们明明只输入了一句话，K采样器到底在里面做了什么？最后怎么就变成了一张完整的图片？说实话，只输入几个字，AI就能生成一张图，听起来确实很神奇，甚至有点像是在变魔术。但它并不是什么无法理解的黑盒，背后其实就是一套非常明确，甚至有些死板的计算过程，只不过这些计算藏在节点和参数后面，所以刚开始看起来会比较抽象。这一节我们就把这套过程拆开来看，你不需要懂复杂的数学公式，也不需要研究那些看不懂的代码，只要先记住一个简单的比喻，就能理解K采样器究竟是怎样把一团杂乱的噪声一步一步变成我们想要的画面。你可以把整个过程想象成一张照片泡在显影液里，画面从模糊不清到轮廓、色彩和细节一点点浮现出来。刚开始时，画面里还没有任何能看懂的内容，只有一团杂乱无章的雪花噪点。不过这里要稍微说明一下，上节课的空Latent节点主要负责准备前空间里的画布尺寸和批次数量，它本身并不是噪声。真正开始采样时，K采样器会根据随机种子，在这块画布上生成初始噪声。

**[00:01:40]** 接下来，模型也不是一下子就把整张图画出来，而是要经过很多轮计算。每一轮，它都会判断眼前这团信息里，哪些更像噪声，哪些更接近我们提示词中描述的内容，去掉一小部分噪声，同时让画面朝着提示词要求的方向靠近一点。这样一轮一轮的处理下去，最开始完全看不出内容的噪点，会慢慢出现大致的构图和轮廓，接着人物、物体和空间关系逐渐稳定，再往后，色彩、光影、材质和细节一点点补充进来，最后才形成一张完整清晰的图片。这个一轮一轮去掉噪声，让画面逐渐浮现的过程，专业上叫做扩散模型的迭代去噪。也可以理解为反向扩散过程。那模型到底是怎么学会去噪的呢？在训练阶段，工程师会先拿一张真实图片，给它加入一定程度的随机噪声，然后把这张带有噪声的图片交给模型，让模型判断这里面加入的噪声到底是什么。因为这些噪声是人为加入的，所以正确答案是已知的。模型猜错了，就根据误差调整内部参数，调整完以后再换一张图片，换一种噪声强度，继续让它猜。这个过程会在海量图片上反复进行。时间久了，模型就逐渐学会了不同程度的噪声中可能隐藏着什么样的画面结构，以及应该去掉哪些噪声才能让画面变得更清晰。不同类型的模型在训练时预测的具体目标可能略有区别，但现阶段大家可以先把它理解成学习识别和预测噪声。等到真正生成图片时，整个方向就反过来了。

**[00:03:19]** 模型不再从一张真实图片开始，而是从一团随机噪声出发。每进行一轮，它都会预测当前画面中应该去掉哪些噪声，再由采样器和调度器按照一定的方式，把画面推进到噪声更少的下一个状态。与此同时，我们写下的提示词也会一直参与这个过程，告诉模型最终应该朝着什么样的内容、风格和画面方向去靠近。它更像是一张导航地图，在每一轮去噪时不断提醒模型，接下来应该往哪个方向走？什么内容应该保留？什么样的画面更符合我们的要求？模型就这样从一团纯噪声开始，一步一步往回推，噪声越来越少，画面也越来越清楚，最后才生成我们看到的完整图片。这也是为啥K采样器里会有个采样步数这个参数。

**[00:04:10]** 上节课咱们用Image Turbo演示的时候，步数设成8步就能出图了。这个步数代表的就是刚才说的擦噪点的动作，要重复做几轮。步数越多，每一轮擦掉的噪声比例就越小，擦的越细致，模型有更多机会去修正细节，让结构更合理，通常画面质量也会更稳定。但代价就是步数越多，等待的时间也越长，因为每一轮都要重新调用一次模型去计算。

**[00:04:38]** 像Image Turbo这类专门做过加速优化的新模型，因为在训练阶段就针对用很少的步数也能收敛出好结果做了特殊处理，所以步数少也能出不错的效果，这也是它生成速度快的核心原因。而没有做过这种优化的传统模型，步数太少的话，画面往往会显得模糊，结构不完整，因为模型还没来得及把噪声擦干净。

**[00:05:04]** 这里有个特别容易被忽略，但其实很关键的点，刚才说的一轮一轮擦噪声的动作，并不是直接在咱们最终肉眼看到的那张像素图片上进行的。而是在一个经过压缩的空间里进行的。这个空间就叫潜空间，英文是latent space。为啥要多此一举先压缩再计算呢？答案就是为了速度。咱们随便举个例子，一张1024×1024的图片，算下来总共有超过100万个像素点，而且每个像素点还有红、绿、蓝三个通道的数值，数据量非常庞大。如果模型每一轮去噪都要直接在这么大的一堆数字上重新计算一遍，那速度会慢到没法忍受，可能生成一张图要等几分钟，甚至更久。

**[00:05:49]** 所以现在主流的做法是先用一个叫VAE的模型，把这张完整尺寸的图片压缩成一个小得多的数据块。这个压缩比例通常是长宽各缩小8倍左右，数据量一下子就小了几十倍，甚至上百倍。所有的加噪、去噪、采样、运算全部都在这个压缩后的小空间里进行，算完之后再放大还原回正常尺寸。

**[00:06:13]** 这么一倒腾，计算效率能提升好几个数量级，这也是为什么现在的AI绘图工具能做到几秒钟到几十秒就出一张图，而不是等上老半天。这也顺带解释了为啥上节课那个准备画布的节点叫空latent，而不是直接叫空图像，因为它准备的其实是压缩空间里的那一小块数据。不是咱们肉眼能直接看懂的那张图，得等到最后经过解码才会变成正常的图片。结合上节课认识的那几个节点，整个生图过程其实可以理解成三个角色在分工合作，谁都不能少。

**[00:06:50]** 第一个角色是CLIP，上节课咱们管它叫翻译员，因为咱们写的提示词是人类语言，是中文或者英文的一段文字，但模型内部处理的是一串一串的数字向量，它没法直接读懂文字。所以得先经过CLIP这一步，把文字转换成模型能理解的数字信息。这个转换出来的东西专业上叫条件向量。正向提示词经过CLIP转换后，会变成一份告诉模型往这个方向靠的信息。负向提示词经过CLIP转换后，会变成一份告诉模型离这个方向远一点的信息。这两份信息都会传给K采样器，在后面每一轮去噪的时候，被模型参考。

**[00:07:32]** 第二个角色是UNET，也就是加载在UNET模型加载器里的主模型，比如咱们用的ZIMAGE TURBO，它才是真正干活画画的。是整套流程里体积最大也最关键的模型。K采样器每转一轮，实际上都是把当前那团噪声数据，加上CLIP给的正负向条件向量，一起丢给UNet，问它照着这些条件来看，现在这团数据里哪部分属于噪声，应该被去掉多少？画面结构应该往哪个方向调整？UNet给出一个预测结果，K采样器就根据这个预测，把当前的数据往前推进一小步，让它更接近一张有意义的图。

**[00:08:14]** 这么一问一答，一轮一轮的重复。重复的次数就是咱们设置的采样步数，噪声数据就这样一步步演变成一份有清晰结构的潜空间图像。第三个角色是VAE，上节课说的显影机。其实VAE在整个流程里干了两件事，一件是刚才提到的，在最开始把大图压缩进潜空间。另一件也是这里要讲的，是在K采样器算完之后，把那份压缩过的潜空间数据重新解码，放大，还原成正常尺寸，人眼能看懂的像素图片。没有这最后一步解码，咱们拿到的只是一堆压缩过的数字。压根看不出是张什么图，必须经过VAE解码，这一步才能变成能看、能保存、能发朋友圈的那张真正的图片。

**[00:09:01]** 现在咱们把整套原理跟上节课搭的工作流对应起来，完整走一遍、理一遍数据是怎么流动的。咱们写好的提示词，先经过CLIP翻译成模型能懂的条件向量，正向、负向分成两路，一起传给K采样器。与此同时，空Latent节点准备好一块随机噪声的潜空间画布，也传给K采样器。UNet模型加载器提供的主模型，就在K采样器这里配合正负向条件向量，一轮一轮的对这块噪声画布进行预测和调整，每一轮都朝着正向提示词描述的方向靠近一点，同时躲开负向提示词描述的那些内容。

**[00:09:44]** 这么反复跑完设定的采样步数之后，这块原本只是雪花噪点的潜空间画布，已经演变成了一份有清晰结构、有内容的潜空间图像。最后，VAE把这份潜空间数据解码、放大还原，变成咱们最终能看到、能保存下来的那张图片。理解了这套完整的流程之后，回头再看K采样器里那几个参数，随机种子、采样步数、CFG、采样器、调度器，就会发现它们其实都是在刚才这套流程里，各自控制着某一个具体的环节。先说随机种子，它决定的就是最开始那块噪声画布具体长什么样子，你可以把它理解成生成这团随机噪声时用的一个起点编号。只要模型、提示词、其他参数都完全一样，同样的种子，理论上每次都能复现出一模一样的图片，因为起点一样，模型每一轮的判断也一样，走出来的路径自然就一样。也可以简单的理解为，这是这张图片的唯一身份信息。

**[00:10:45]** 这个参数还有个特别实用的用法，当你调出一张构图挺满意的图，只是想微调一下细节，或者稍微改改提示词的措辞，可以把种子锁死不动，这样能大概率保住原来的构图、姿势和整体布局，只让局部细节跟着变化。反过来，如果你想每次生成的结果都完全不一样，那就把种子设成随机，每次自动换一个新的起点。

**[00:11:10]** 再说采样步数，前面已经讲的比较细了，这里简单归纳一下。步数就是刚才那套擦噪声的动作要重复做几轮。步数越多，每一轮的调整幅度就越小，模型有更多机会去精修细节，画面通常会更稳定、更完整。但步数越多，生成时间也跟着线性增加。像ZImage Turbo这种做过加速训练的模型，8步左右就足够出效果不错的图。没做过这种优化的传统模型，可能得20步、30步，甚至更多才能稳定出图。不过步数不是无脑往上加就好，得先看你用的是哪个模型。很多时候超过某个临界点之后，再加步数对画质的提升已经非常有限了。纯粹是在浪费时间干等着。

**[00:11:56]** 那么CFG值，专业名字叫无分类器引导强度，通俗点说就是模型在每一轮判断的时候，听取你提示词的话，约束力得有多死，这个程度。数值调低，模型会更多的按照自己训练时学到的一般规律去发挥，跟你写的提示词的贴合度可能没那么高，但画面整体往往会显得更自然、更松弛，不那么刻意。数值调高，模型会非常执着的往你提示词描述的方向靠，贴合度会明显提升，但太高了容易出现过度锐化。颜色过饱和，画面结构发僵，这些副作用。

**[00:12:34]** 过去SD 1.5或者SDXL的时代，常见的取值大概在7~10这个区间。现在新出的模型，一般情况下1就已经可以得到很好的一个效果了。不同模型的甜蜜点不太一样，最终还是得结合实际出图效果，自己去尝试，去总结。接下来我们再来看K采样器里两个很容易混淆的参数，采样器和调度器。采样器指的是每一轮去噪时，模型完成噪声预测以后，系统具体采用哪一种数学算法，计算下一步的画面应该往哪里走。常见的采样器包括Euler、DPM++ 2M、DPM++ SDE、UniPC等。第一次看到这些名字，确实很容易一头雾水，但大家可以先把它简单理解成，从一团噪声走向清晰图片时，选择了不同的路线和行进方式。

**[00:13:27]** 不同采样器的计算方式不一样，因此在收敛速度、画面稳定性、细节表现和整体质感上，也可能会出现一些差别。有些采样器速度比较快，即使采样步数不高，也能生成完成度不错的画面。有些采样器则更擅长处理纹理和细节，但通常需要搭配合适的步数与调度器，才能发挥出更好的效果。

**[00:13:51]** 不过在刚开始学习ComfyUI的时候，大家真的不用在采样器上反复纠结，优先使用模型官方推荐的设置，或者直接沿用工作流自带的默认参数，就已经完全够用了。等以后生成的图片多了，再把不同采样器放在相同参数下进行对比。自然就能慢慢找到更适合自己模型和画面风格的选择。

**[00:14:14]** 为了满足大家的好奇心，我也把常见采样器和调度器的特点、适用场景以及推荐搭配整理成了一份对照表，感兴趣的小伙伴可以在评论区自行领取。而调度器负责的则是整个去噪过程中的节奏安排，更准确的说，它决定了从高噪声到低噪声的过程中，每一个采样步骤分别处在哪个噪声等级，以及这些步骤应该怎样分布。你可以把整个去噪过程想象成一段路。虽然总共都要走十几步，但调度器会决定这十几步具体怎么安排，是每一步之间的距离比较均匀，还是前面的跨度大一些，后面的步骤更密一些，又或者把更多计算集中在某一个噪声阶段。不同的安排方式会影响模型在构图、轮廓、纹理和细节上分别投入多少计算。所以采样器和调度器通常需要搭配起来理解。采样器决定每一步具体怎么走，调度器决定这些步骤在整段去噪路程中怎么分配。同一个采样器更换不同的调度器，最终画面的细节、稳定性和整体质感也可能会跟着发生变化。

**[00:15:23]** 这个参数同样建议大家先使用模型官方或者工作流提供的默认搭配，现阶段先知道它在整套流程中负责什么就可以了，不需要一开始就钻进复杂的数学原理里。最后是denoise，也就是去噪强度。在咱们现在讲的纯文生图流程里，这个参数通常是固定的1，代表整个去噪过程是从一团完全随机的噪声开始的。也就是彻头彻尾的重新生成一张图，跟任何已有的图片都没有关系。但等以后大家接触到图生图的时候，这个参数就会变得特别关键。数值越接近1，代表加进去的噪声比例越高，起点越接近纯随机，生成结果也就越像是重新画了一遍，跟原图关联程度越低。那么数值越小，代表保留的原图信息比例越高，起点里混入的噪声比例少。生成结果就会跟原图更接近，改动幅度更小。这就是控制在原图基础上到底改动多少、保留多少的关键参数。

**[00:16:26]** 把这几个参数串联起来看，整套生成逻辑其实就很清楚了。随机种子决定画面从哪一个具体的随机起点出发，采样步数和调度器共同决定去噪过程要走多少轮，以及每一轮的节奏如何分配。采样器决定每一轮采用什么样的计算方式和路径去除噪声。CFG决定生成过程中对提示词的遵循强度。而denoise决定初始噪声介入的程度，也就是模型可以对画面进行多大幅度的重新生成。

**[00:16:58]** 当我们真正理解了这套底层逻辑，以后无论接触什么新模型、新节点，还是新的工作流，在看到这些参数时，都不会觉得陌生。我们不再需要机械的照抄别人给出的数值，而是可以根据自己的生成目标，先判断应该调整哪个参数，再结合实际的出图效果进行反推，逐步找到下一步应该优化的方向。好的小伙伴们，今天这一节的内容就先分享到这里，相信大家现在再回头看整个文生图工作流，它已经不再是一堆看不懂的方块和连线，而是一条从提示词、模型和初始噪声出发，经过采样与去噪，最终生成图像的清晰数据处理流程。理解了这套流程，后面无论是更换模型、修改参数，还是搭建更加复杂的工作流，都会轻松很多。那么我们下节课再见！
