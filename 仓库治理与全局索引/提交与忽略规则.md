# 提交与忽略规则

本仓库保存学习成果、可复用知识和项目源码。`.gitignore` 负责路径与文件类型过滤，提交检查器负责暂存区的忽略规则、运行凭据和 100MB 大小检查，两者配合使用。规则按当前 Python、Java、Web、小程序、HarmonyOS、AI、运维和生活记录的实际内容制定；以后增加技术或新工具时继续维护。

## 可以提交什么

| 内容 | 放置和要求 |
|---|---|
| 学习笔记、课程记录、研究、日记 | Markdown、文本、Notebook；按分类手册放置。小七笔记和处理过的生活图片正常保留。 |
| 自己的代码、工作流、技能 | Python、Java、前端、小程序、ArkTS、ComfyUI JSON、AGENTS.md、CLAUDE.md、SKILL.md 和可复用技能包。 |
| 项目复现清单 | requirements.txt、pyproject.toml、uv.lock、package.json、package-lock.json、pom.xml、oh-package-lock.json5 等；锁文件应提交。 |
| 可共享配置 | 不含真实密钥的 YAML、JSON、TOML、Dockerfile、Compose、CI 配置；`.env.example`、`.env.sample`、`.env.template` 中只写空值或明确的示例值。 |
| 图片、音视频、图表和资料 | 有保存与分享权限的图片、PDF、课件、文档、课程 ZIP、小型数据；每个文件不超过 100,000,000 字节。assets 是附件，不代表不能提交。 |
| 测试数据 | 无真实账号、Cookie 或用户记录的 fixtures。演示数据库可以放在项目的 fixtures 目录，运行过程中变化的数据库不能当演示数据提交。 |
| 必需的构建启动器 | Maven／Gradle wrapper JAR 已设例外，避免把启动器当普通依赖包过滤。 |
| 特定研究附件 | 已有 VMware 汉化研究中的 zh_CN DLL 作为该研究的资源例外保留，不能据此放行其他运行依赖。 |

“默认允许”不等于自动入库：新增资料需要查看实际内容和大小。HDF5、bin、JSON、ZIP 既可能是资料，也可能是权重、凭据或安装包，不能只凭后缀判断；模型权重应放 weights、checkpoints 或 models_files 等忽略目录，来源与实验结果另外写成文档。

## 不提交什么

| 内容 | 典型例子 | 如何保留用途 |
|---|---|---|
| 安装后的依赖与环境 | node_modules、oh_modules、.venv、site-packages、手工拷贝的 JAR／DLL | 提交依赖清单、锁文件和安装步骤；本机文件可以保留。 |
| 缓存及构建结果 | __pycache__、.hvigor、.preview、build、dist、target、out、coverage、class、pdb | 提交源码和构建方法；不要把唯一一份手写笔记放进这些目录。 |
| 本机配置及会话 | .idea、.vscode、local.properties、project.private.config.json、.claude/settings.local.json、浏览器 user_data 中的会话目录 | 可复用部分整理成配置示例或说明，不直接提交整个本机状态。 |
| 真实运行凭据 | .env、私钥、token、Cookie、真实账号密码 | 只留变量名与无真实值模板。忽略文件无法发现其他代码里写死的密钥，提交时仍需检查内容。 |
| 运行数据库及临时文件 | db.sqlite3、email_tasks.db、dump.rdb、appendonly.aof、Office 的 ~$ 锁文件、日志 | 保留 migrations、数据库 schema、脱敏 fixture 或操作教程。 |
| 模型与训练输出 | pt、pth、ckpt、onnx、safetensors、gguf、weights、runs | 登记模型来源、版本、参数、数据与结果，不存大权重。 |
| 第三方镜像与安装包 | 已登记的 RAGFlow、Ultralytics、Redis 镜像，exe、msi、iso、7z、rar | 保存来源与学习结论。课程 ZIP 不一概忽略，但安装包仍不能混在课程资料里。 |
| 超过大小限制的文件 | 普通 Git 文件及 LFS 指针引用的真实内容 >100,000,000 字节 | 改为外部资源登记；本仓库不通过 LFS 绕过这一限制。 |

不要用 `git add -f` 绕过规则。提交钩子也会检查“已被强制跟踪但应当忽略”的文件并拒绝提交。子项目自己的 `.gitignore` 仍生效；排查具体文件使用 `git check-ignore -v --no-index -- "文件路径"`。

## 空目录与本地文件

2026-09-14 已确认并清理 19 个旧顶层空目录及 5 个空子目录，只移除了没有文件的目录。原有知识文件已迁入 10 个分类。Git 不记录真正的空目录；新建空分类也不会出现在远程，只有需要明确入口时才添加有内容的 README。

项目内部的运行目录、被忽略的环境和模型仍可能存在于磁盘，这是保留的本地工作资料。`.git/` 是版本库数据；`.migration-local/` 是被忽略的迁移工具与校验证据，均不作为知识内容提交。

现状是“目录迁移、导航、ID 和路径映射已整理并核验”，不代表已经逐篇改写了所有历史笔记，也不代表所有历史项目都已重新启动测试。网站后端的正文解析、搜索和数据库同步仍按同步契约接入。

## 每次提交前

先运行 `git status --short`，再按具体文件或目录执行 `git add -- "路径"`。检查 `git diff --cached --stat` 和 `git diff --cached`，确认没有依赖、运行状态和真实凭据。

运行以下检查，全部通过后提交：

```powershell
python -X utf8 仓库治理与全局索引/工具/check_staged_files.py
python -X utf8 仓库治理与全局索引/工具/test_repository_policy.py
git diff --cached --check
git commit -m "描述本次学习或整理内容"
```

本机已安装 pre-commit 检查。Git 克隆不会自动安装钩子；换电脑后按治理 README 的说明安装。检查器可手动运行，不能用未经审阅的强制提交替代它。

## 跟踪清理与历史

`.gitignore` 不会自动移除已经跟踪的文件。补充清理只让匹配文件退出当前索引，保留本机字节；清单见 `索引/忽略规则补充清理.json`。文件索引的 `files` 表示仍在同步的迁移文件，`retiredFiles` 保留退出同步文件的原 ID、路径与校验证据。

旧提交中的既有文件不会被这次整理抹去；本次不重写历史。推送的是原有迁移批次和本次规则整理提交，普通文件和 LFS 内容均检查 100MB 限制。
