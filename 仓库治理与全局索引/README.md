# 仓库治理与全局索引

本目录维护分类入口、路径迁移映射、文件索引和提交检查工具。分类说明见[仓库目录分类手册](../仓库目录分类手册.md)。

[目录导航](_index.md) · [实际目录树](索引/实际目录树.md) · [迁移对照表](目录迁移对照表.md) · [同步契约](网站同步契约.yaml) · [迁移记录](迁移记录.md)

## 后端读取

运行 `python -X utf8 仓库治理与全局索引/工具/catalog.py --export`，标准输出为整个 Git 仓库的文件和目录 JSON，包含稳定 ID、当前路径和 parentId。目录索引中人工整理的入口用于知识图谱；自动发现的工程内部目录默认 `site: false`，仍可在目录浏览器中读取。

`--resolve "旧路径或稳定ID"` 查找迁移后入口；旧集合目录拆分时返回多个目标。`--verify` 检查迁移快照中的文件是否仍存在、受跟踪且内容一致。该脚本是参考读取器；Markdown/PDF 等正文解析、搜索、数据库增量同步和 HTTP 接口由网站后端实现。

目录入口优先读取 `_index.md`，其次 `README.md`；原工程已有 README 时，用单独的 `_index.md` 保存目录元数据，保留原说明。新增文件不受迁移快照限制；新增内容的 Front Matter ID 应优先于路径兜底 ID，并在首次导入后持久化。

迁移按主题或完整项目分批，每批核验文件完整性、路径映射和暂存区大小后单独提交。已退出跟踪的文件仍保存在本机，不删除本地依赖、模型和第三方源码。

## 提交检查

运行 `python -X utf8 仓库治理与全局索引/工具/check_staged_files.py` 检查完整暂存区，包括 Git LFS 指针声明的实际文件大小。阈值为 100,000,000 字节，超过阈值或提交真实 `.env` 文件时返回非零退出码。

`.gitignore` 按名称和路径过滤，无法表达大小限制。本机已安装 `pre-commit` 检查；重新克隆时，把本目录 `hooks/pre-commit` 安装至 `git rev-parse --git-path hooks` 返回的目录。若已有同名钩子，应在原钩子中串联检查命令。保留仓库原有 Git LFS 钩子。

索引中的“退出跟踪文件”只记录路径，不包含文件内容或凭据。历史提交未改写，原有历史对象仍存在。
