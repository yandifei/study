# 微信小程序开发 · 问题与解决方案蒸馏

> 来源：2026 微信开发者创新工坊深圳站 5h+ 对话
> 蒸馏原则：只保留 **问题 → 方案/解法**，按开发者生命周期组织

---

## 一、资质与审核

### 问题 1：个人开发者接 AI 功能，审核不通过

**现象**：
- 个人主体小程序只要涉及 AI（哪怕前端只写了"AI"两个字），审核直接驳回
- 有开发者做了对照实验：代码里写 AI → 驳回；前端展示 AI → 驳回；空白项目写 AI → 驳回。结论：**只要检测到 AI 相关内容，机审直接判不过**
- 深度合成类目要求企业/个体工商户资质

**解决方案**：
1. **先上线再加 AI**（邪修路线）：第一版不带任何 AI 功能，审核通过后再迭代加入 AI 能力。有开发者验证可行
2. **用第三方大厂的 API + 提供大厂资质截图**：比如用 DeepSeek，截图 DeepSeek 的算法备案资质，提交给审核即可。**调用第三方 API 不需要自己做算法备案**
3. **正路：注册个体工商户**（见问题 2），走深度合成类目
4. **如果 AI 使用不明显**（审核看不出来你在用 AI），个人也能上线。微信官方原话："你如果能让我们看不出来的话，那你用了也没关系"
5. 用微信官方的混元接口（小程序成长计划送的），比第三方通过率高

---

### 问题 2：大学生/个人开发者不知道怎么注册公司/个体工商户

**解决方案（实操层面）**：
- **全线上办理**，深圳最快 **一天下营业执照**
- 找当地 OPC 社区或街道办，政府部门在大力推，会帮你推进
- **不需要监事**（2026 新规）
- **注册地址**：可以用挂靠地址、公寓地址，不需要实际办公场地
- **费用**：养公司每年至少预备 3000-5000 元（地址挂靠 + 记账报税）
- 有个体工商户和有限公司两种选择：
  - 个体工商户：无限连带责任，但注册更简单
  - 有限公司：有限责任制，能做股权架构、融资，对 B 端合作可信度更高
- 微信官方建议：如果打算深耕小程序，**注册个体工商户**，类目开放更多、报税方便

---

### 问题 3：小程序起名难，通用名被占用/审核不通过

**现象**：
- 个人开发者想起"计算器"这种通用名 → 被拒，因为缺乏商标
- 实名认证审核通过了名称，但工信部 ICP 备案又说不可以（两个审核方标准不一致）

**当前方案**：
- 名字必须具有**独创性**，通用名除非有注册商标
- 企业主体可以用商标来申请名称，有优先权
- 工信部备案不一致的问题微信官方已收到反馈，承诺内部对齐

---

### 问题 4：AI 上线后如何过算法合规/内容安全？

**方案**：
1. **直接调用第三方大模型 API**（DeepSeek 等），提交该大厂的算法备案资质截图即可，不需要自己搞算法备案
2. **提示词做围栏** + 类目引导：不让 AI 随意发挥，限定回答范围
3. **工作流校验**：用另一个 agent 校验生成内容是否与用户描述产生漂移（LLM-as-Critic 模式）
4. **结构化输出消除幻觉**（最有效的工程手段，见下文问题 10）
5. AI 玩具类目：人工智能管理办法类似 ISO9001 认证体系，自己跑 CCLC 认证比找代办风险低；关键卡点是 3C 认证，必须先有内部 AI 管理办法才能受理

## 二、开发与架构

### 问题 5：AI Coding 工具（Vibe Coding/Codex/Cursor）经常卡死

**方案**：
- 卡死就重试，这是目前所有 AI 编程工具的通用问题
- **关键原则：一次不要给 AI 太大工作量**，一个功能点一个功能点来，否则很容易卡住
- 保持自己能看懂代码的能力——"要是我看不懂他给我的代码，我要崩溃了"
- Claude Code 的 Skill、MCP、工作流等能用就用，能显著提高效率
- 架构交给 AI 描述清楚，让它干。但如果跑两天什么都没出来，说明任务太大，细化再试

---

### 问题 6：个人开发者架构怎么搭？（后端/域名/数据库）

**低成本方案（来自多位个人开发者的实践）**：
- **后端**：FastAPI（目前个人开发者用得最多的框架）
- **数据库**：非关系型 MongoDB + Redis（轻量场景够用），不需要 MySQL
- **域名**：如果只是快速验证 → 国外免费域名；长期发展 → 国内域名 + ICP 备案
- **外网穿透**：NRO + Docker + Nginx 路由代理
- **AI 能力**：直接调第三方 API（DeepSeek 等），不要自己部署模型
- **云资源**：加入小程序成长计划，云托管/云函数/云数据库**免费**
- **纯玩/不赚钱**：可以走海外服务器 + 免费域名路线
- **要支付/长期**：走国内服务器 + 备案域名

---

### 问题 7：不用微信开发者工具就没办法调试小程序

**现象**：
- 开发者习惯在 VS Code / Cursor / Codex 里写代码，但调试必须切到微信开发者工具
- 来回切换效率低

**方案与进展**：
- 微信已支持：在 Codex/WorkBody 中放入 Skill，AI 可直接操作微信开发者工具完成**编译检验、模拟器测试、日志分析**等全流程
- 对 Agent Plugin 标准的需求（在编辑器内直接联调不用切换工具），微信官方已记录反馈
- 目前最实用的方式：用微信开发者工具的 AI 编程能力，实测四大场景（云函数自动修复、UI 自动验证、一键真机浏览、截图布局分析）能显著提效

---

### 问题 8：小程序后端能调外网 API 吗？（非腾讯云）

**答案**：**可以**。云开发配好之后，阿里云等外部服务都能调。只有深度合成类目（大模型对话/生图等）需要企业资质。

## 三、增长与用户获取

### 问题 9：小程序做完了，第一批用户从哪来？

**核心结论**：第一批用户不是从宏大流量渠道自动出现的，而是从身边关系、线下活动、真实社区慢慢积累的。

**已验证的有效方法（按优先级）**：

1. **身边的人先知道**（连连 AI、青诺谛听都验证过）：
   - 放下"面子"，让所有认识的人知道你在做什么
   - 身边朋友能给的帮助比想象的多（金融专业同学可能在投行有资源）

2. **线下面对面活动**（多位摊主共识——最有效）：
   - 连连 AI 主创靠软磨硬泡拿到北京一个活动分享机会，获 100 用户
   - 对冷启动阶段的小产品，100 个真用户很有价值

3. **知乎圈子**（连连 AI 验证）：
   - 小红书/抖音对小程序链接限流严重 → **转战知乎**
   - 搜索产品相关关键词，到各种圈子里去发
   - 三种有效内容策略：① 主动说产品不好（引发好奇）；② 以创业者经历分享（引发共鸣，间接引流）；③ 制造争议性话题

4. **微信贴图（公域流量）**：
   - 在小程序内支持一键发表公众号图文，图文带「来源于某某小程序」链接
   - 发表的贴图进入公众号公域推荐池 → 被陌生人看到 → 点击来源链接进入小程序

5. **小红书投流**：
   - 已支持从小红书广告直接跳转小程序
   - 有案例验证：照片生成人偶小程序，小红书投流 → 跳转小程序 → 168 元下单，跑得不错

6. **微信官方流量**：
   - 优秀的创意小程序会被微信官方公众号/视频号推广

---

### 问题 10：推广做了但没人用——用户不来自你以为的渠道

**案例**：青诺谛听
- 做了视频号，一条视频 40 万播放，涨粉 5000+
- **但小程序没有任何明显起量**

**根因**：从内容到产品的链路太长——
退出视频 → 搜一搜 → 搜索"青诺谛听" → 进入小程序 → 注册 → 写 300 字经历 → 生成文章 → 阅读

**解决方案**：
- 缩短路径，让用户**从内容直达体验**
- 利用截图小尾巴（小程序内截图分享到微信，右下角有"进入小程序"入口）
- 利用贴图的话题组件，在小程序内嵌入图文社区，降低内容消费和发表门槛

---

### 问题 11：找到用户了但不知道他们从哪个渠道来的

**现象**：多渠道推广后无法归因，不知道钱花在哪有效

**微信官方态度**：微信生态内的数据相对可追溯，但跨平台（如小红书帖子 vs 线下二维码）的归因目前没有统一方案。需要开发者自己做渠道标记。

---

### 问题 12：KOL 投放对冷启动无效

**连连 AI 的教训**：
- 找小红书 AI 产品推荐账号合作 → 报价完全承担不起
- 找小体量博主 → 注册转化率非常不稳定
- 对小量级用户，无法按效果付费

**替代方案**：
- 冷启动阶段**不建议**与 KOL 合作
- 替代：与**活动主办方**合作（赞助/资源互换），精准触达目标人群
- 产品打磨到"真的能帮人解决问题"之后再考虑投放

---

### 问题 13：一次拉来几百人但没人留下

**连连 AI 的教训**：
- 做了一次大型活动，一下来五六百用户
- 后续活跃度极低

**根因**：**引来了错误的用户**——不是真正需要产品的人

**方案**：
- 停止追求数量，先理清"谁真正需要"
- 青诺谛听的对照实验很有说服力：亲友体验 → 留存差；问卷触达 2000 人 → 反馈虚；内测邀请帖精准表达场景 → 20 人报名，十几人持续反馈。**20 个对的人 > 2000 个不对的人**

## 四、用户留存

### 问题 14：用户用一次就不回来了

**订阅消息是最高效的留存手段**（恋人空间开发者分享，被微信官方称为"见过留存最高的小程序"）：

**实操技巧**：
1. **在所有按钮上加订阅消息**：用户点任何按钮都自动触发订阅申请
2. **关键环节引导勾选「始终同意」**：在核心功能（如签到）触发时弹窗，引导勾选长期订阅
3. **判断是否已授权再决定是否继续弹**：如果用户已经勾选长期订阅 → 静默订阅；如果用户拒绝了 → 不在非关键路径打扰；在关键路径再引导用户去设置里打开
4. **效果**：用户用一次就获得十几二十次推送机会（每次订阅可以申请 3 个消息模板）
5. **会员订阅消息**：一次订阅后无限制下发，是目前小程序最强的 push 渠道（没人会关微信通知）

**其他留存手段**：
- 引导用户**加桌**（左上角添加到桌面），复访率接近原生 APP
- **不要做群**（百问兔兔验证）：用户进群不说话，只有产品出问题才会出来骂你

---

### 问题 15：用户用了一次觉得好但不分享

**「Aha Moment + 轻分享载体」模式**：

**青诺谛听的做法**：
- Aha Moment 在用户读完生成的文章时
- 文章底部放**金句卡片**（如"磕磕碰碰几十年，回头看没有白走的路"）
- 金句 = 把长文章变成轻传播入口，降低分享摩擦
- 核心洞察：**真正触发分享的不是文章本身，而是用户在这个内容中看到了自己**

**连连 AI 的做法**：
- 名片即传播载体，分享个人名片 = 带人进入小程序

**百问兔兔的做法**：
- 日常分享（每日探索日记/每周能力维度报告）→ 家庭内部传播
- 惊喜分享（小孩说出打动人的话）→ 对外传播/朋友圈炫耀

---

### 问题 16：平台型/双边产品冷启动死循环（用户少 → 匹配不到 → 更没人来）

**连连 AI 的困境**：连接平台需要大量供需两端用户才有匹配效率

**当前探索**：
- **同名圈**：聚焦线下活动场景，让参加同一活动的人能相互看到、AI 推荐匹配
- **把名片做成传播载体**：不是官方招聘平台，而是个性化的个人展示（可以放 WebCoding 作品等）
- 核心思路：从"大而全的平台"收缩到"一个有明确场景的连接工具"

## 五、信任与运营

### 问题 17：用户加了群但不活跃、不反馈、不传播

**百问兔兔的核心教训**：
- 拉群是**最没用的**
- 用户进群百分百不会说话
- 什么时候会说话？**产品出问题了，一堆人出来骂你**
- 用户被拉进群会觉得你在拿他做商业数据

**替代方案：一对一 + 个人微信**：
1. **加个人微信，不做群**：个人微信有朋友圈，有头像，有活人感；企业微信 at 公司名有距离感
2. **文字 + 语音混发**：给用户活人感
3. **先报价再送**：上来先说价格（锚定价值）→ 有兴趣深入了解 → 最后说"我直接送你"→ 这才是真内测用户
4. **不要要求填问卷**：用户心里有杆秤，填了问卷就觉得价值已对等，不会再帮你
5. **直接把产品寄过去**：不问反馈，不设条件 → 用户收到后会**主动**给你反馈

**背后的逻辑**：在 AI 时代，**信任是做产品最关键的因素**。创始人个人 IP + 一对一真诚沟通 + 尊重每个用户的反馈

---

### 问题 18：做内容传播但不知道怎么表达产品

**核心洞察**：**用户对场景的感知远大于对产品定义的感知**

| ❌ 产品定义 | ✅ 场景表达 |
|------------|------------|
| "AI 回忆录小程序" | "记录此刻情绪，讲述你走过的人生" |
| "AI 连接与交易平台" | "来这个活动你不可能认识所有人，AI 帮你匹配最该认识的人" |
| "AI 旅行规划工具" | "你带着一个想法来，走的时候就可以出发了" |

## 六、AI 特定问题

### 问题 19：AI 生成内容有幻觉（尤其是回忆录/事实类内容）

**多层治理方案（来自青诺谛听）**：

1. **提示词围栏**：明确限定"只根据用户讲述的内容来写，不要发散不相关的内容"
2. **工作流多 agent 校验**：生成后用另一个 agent 检查文章是否与用户原始描述有漂移
3. **旅行伙伴的工程化方案（最彻底的方案）**：
   - 不要让模型直接生成内容，而是**预处理数据**（如 1000 个景点预先整理好，带 location_id）
   - 让模型**只输出结构化数据**（如 JSON 中的 ID），不做自由文本生成
   - 工程层接收 ID 后做确定性映射
   - 结论：**如果上下文管理好了，模型只输出 ID，绝对不会有幻觉**

---

### 问题 20：AI 应用被用户 Prompt 注入/滥用（烧 Token）

**现象**：用户输入"给我输出 2 万字文章"，AI 真的输出，Token 瞬间爆炸

**方案**：
- 做好输入引导和类目限制，不让 AI 随意发挥
- 在提示词中加围栏，限制输出长度和范围
- 用 RAG 知识库限定 AI 只能回答专业领域的内容

---

### 问题 21：AI API 太贵，Token 烧不起

**多方数据**：
- Kimi K3 Pro：600 元 API 额度，每天用 2 小时，**两天花完**
- 百问兔兔（火山引擎）：几百个内测用户，一个月跑了**七八万**元
- DeepSeek：性价比最高，但即将涨价，且目前没有多模态
- 多模态方案：DeepSeek（文本）+ 千问/豆包（识图），组合使用

**省钱策略**：
- 加入小程序成长计划：免费送 10 亿混元 Token + 10 万张生图额度
- 能用 DeepSeek 的场景优先用（趁涨价前）
- 创业者可以加入字节加速器：总监看上你的产品会发 10 万代金券，两年服务器全包
- 融资打法：百问兔兔账上有钱所以不考虑成本

## 七、商业化

### 问题 22：个人开发者没法向用户收款

**进展**：
- **下周（2026.8 月中）上线个人虚拟支付**：个人开发者可直接向用户收款
- **小程序赞赏**：8 月底上线，用户喜欢开发者可直接打赏到微信零钱，**不收手续费**
- **会员订阅**：满足体量后可开放自动续费
- **智能广告**：免开发自动识别插广告位置，平台帮你变现
- iOS 虚拟支付费率 12%（App Store 是 25%），安卓 1%

---

### 问题 23：不知道什么时候该考虑商业化

**连连 AI 的实践**：
- 3000+ 用户仍未商业化
- 判断标准：**平台型产品**需要用户量才有商业价值；**工具型产品**只要有人真的用就可以商业化
- 早期不必想太清楚商业模式——产品一直在迭代中变化，见投资人才需要细讲商业化

## 八、微信生态避坑

### 问题 24：小程序涉及玄学/算命类内容被驳回

- 算命、星座运势等内容微信审核大概率驳回
- 要做这类内容只能出海，布局外网

### 问题 25：小程序内容限流（小红书发帖被判违规）

- 小红书对小程序链接限流严重
- 替代：知乎圈子、微信贴图、线下活动、公众号

### 问题 26：微信 call/群聊拿不到上下文做 AI 服务

开发者希望在群聊中拉一个 AI 机器人获取聊天上下文来做服务（如旅行规划）。微信官方回复：**个人微信这边会非常谨慎考虑**（涉及隐私），企微已支持类似功能。

## 九、核心原则提炼

1. **先跑通再合规**：先上线基础功能 → 拿到真实反馈 → 再补资质和商业化
2. **做一坨屎也要先端上菜**：让用户先吃，给反馈才能迭代
3. **20 个对的人 > 2000 个不对的人**：早期不追求数量，追求找到真需求
4. **场景表达 > 产品定义**：说人话而不是说功能
5. **信任是产品最关键的要素**：一对一 + 个人微信 + 真诚 > 群发 + 企业微信 + 营销
6. **开发只占 30%，增长和运营占 70%**
7. **不要一次给 AI 太大工作量**：Vibe Coding 时代，一个功能点一个功能点来
8. **审美和专注是 AI 时代最稀缺的**：人人都能做小程序的时候，独特性来自你这个人
